# Рассылка по сделкам Битрикс24 — инструкция для ассистента

Когда пользователь просит «найти сделки по условиям и отправить им письмо»:

1. Создай/обнови файл кампании в `campaigns/` (фильтр в секции `[filter]`, тема, текст письма
   в `templates/`). Не зашивай условия в код. Если неясно, как называется поле, воронка
   или стадия, запусти `python -m bitrix_mailer fields`.
2. Запусти предпросмотр **без отправки**:
   `python -m bitrix_mailer preview campaigns/<файл>.toml --no-prompt`
   (дополнительные условия — флагами `-w "Сумма>100000"`).
3. Покажи пользователю статистику целиком (найдено / с контактами / с валидным email /
   уже получали / будет отправлено), причины исключения и пример письма.
4. **Жди явного подтверждения** пользователя. Без него `send` не запускать.
5. После подтверждения: `python -m bitrix_mailer send <id> --yes`.
6. Покажи итоговый отчёт (`python -m bitrix_mailer report <id>`), особо — ошибки и письма,
   не подтверждённые в Timeline.
7. Статус «прочитано / не прочитано»: тот же `report <id>` — при каждом запуске подтягивает
   из Битрикс24, кто открыл письмо (только чтение). Работает для `via = "bitrix"`.

## Изменение сделок (стадия, ответственный, поля)

Менять сделки можно **только когда пользователь сам об этом попросил** — и тоже через
план и подтверждение:

1. `python -m bitrix_mailer update -w "<условие>" ... --set "Стадия=В работе" --no-prompt`
   (или `--deals 12,15`, или `--campaign campaigns/<файл>.toml` — взять фильтр кампании).
2. Покажи пользователю план целиком: сколько сделок найдено, сколько изменится, примеры
   «Стадия: Свободные → В работе», что пропущено и почему.
3. **Жди явного подтверждения.** После него: `python -m bitrix_mailer update-apply <id> --yes`.
4. Покажи результат и напомни про откат: `python -m bitrix_mailer update-undo <id>`
   (тоже только по просьбе пользователя и с подтверждением).

Сменить стадию после рассылки: секция `[after_send]` в файле кампании (только если
пользователь попросил). План изменений виден в preview; подтверждение отправки
распространяется и на него — скажи об этом пользователю явно.

## Что запрещено всегда

Создавать и удалять лиды/сделки/контакты/компании; изменять контакты и компании;
переносить сделку в другую воронку; менять привязки сделки (контакты, компанию) и
служебные поля; менять сделки без просьбы и подтверждения пользователя.
Клиент (`bitrix_mailer/client.py`) технически блокирует такие вызовы, а `crm.deal.update`
пропускает только клиент с `allow_deal_updates=True`, который создаётся после
подтверждения. Не ослабляй эту защиту без явного разрешения пользователя.

Тесты: `python3 -m unittest -v`
